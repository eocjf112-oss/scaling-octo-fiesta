# Jarvis Memory

이 문서는 Jarvis가 장기적으로 유지해야 하는 핵심 정보를 기록하는 기본 메모리 문서입니다.
아직 확정되지 않은 임시 정보는 넣지 말고, 반복적으로 재사용되거나 의사결정에 영향을 주는 사실만 정리합니다.

## 1. 사용 목적

`MEMORY.md`는 다음 정보를 축적하기 위한 기준 문서입니다.

- 사용자 선호
- 작업 스타일
- 고정 규칙
- 프로젝트 공통 원칙
- 반복되는 요청 패턴
- 중요한 의사결정 기록

## 2. 작성 원칙

1. 짧고 명확하게 쓴다.
2. 확인된 사실만 저장한다.
3. 바뀔 수 있는 정보는 날짜나 맥락을 함께 적는다.
4. 프로젝트 전용 정보는 가능하면 `Projects/`에도 함께 남긴다.
5. 세부 메모가 많아지면 `Memory/` 폴더 아래 주제별 파일로 분리한다.

## 3. 기본 메모리 구조

아래 항목을 필요에 따라 계속 갱신합니다.

### 사용자 선호
- 기본 언어: 한국어
- 설명 방식: 명확하고 실용적인 구조 선호
- 산출물 방향: 실제로 바로 사용할 수 있는 문서와 구조 선호

### 작업 원칙
- 문서화와 구조화를 우선한다.
- 재사용 가능한 자산은 템플릿으로 남긴다.
- 폴더/파일 역할을 명확히 구분한다.

### 반복 규칙
- 설명은 한국어로 제공한다.
- 작업공간은 목적별 폴더로 나누어 관리한다.

### 현재 작업공간 기준
- 루트 작업공간 이름: Jarvis
- 핵심 운영 문서: `README.md`, `MASTER_PROMPT.md`, `MEMORY.md`
- 핵심 폴더: `Projects`, `Memory`, `Prompts`, `Automation`, `Documents`, `Logs`, `Temp`

## 4. 추천 확장 방식

정보가 늘어나면 다음처럼 세분화할 수 있습니다.

```text
Memory/
├── user-preferences.md
├── communication-style.md
├── decision-log.md
├── project-rules.md
└── recurring-workflows.md
```

## 5. 업데이트 예시

### 예시 1
- 항목: 사용자 선호
- 내용: 답변은 한국어, 결과물은 실사용 가능한 형태를 선호

### 예시 2
- 항목: 반복 규칙
- 내용: 새 프로젝트는 `Projects/` 아래 독립 폴더로 생성

### 예시 3
- 항목: 운영 습관
- 내용: 재사용 프롬프트는 `Prompts/`, 자동화 스크립트는 `Automation/`에 정리

## 6. 메모리 점검 체크리스트

- 이 정보가 다음 작업에도 유효한가?

- 임시 메모가 아니라 장기 자산인가?
- 더 적절한 별도 파일로 분리해야 하는가?
